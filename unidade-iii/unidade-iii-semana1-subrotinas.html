Por que modularizar código?

Imagine um sistema de vendas que precisa calcular, para cada produto, o valor final a pagar: parte do preço multiplicado pela quantidade, com um desconto aplicado e depois o ICMS (imposto sobre circulação de mercadorias) somado em cima do valor já descontado. Sem funções, o código fica assim para cada produto vendido:

int main(void) {
    // Produto 1
    float subtotal1 = 89.90f * 3;
    float desconto1 = subtotal1 * (10.0f / 100);
    float comDesconto1 = subtotal1 - desconto1;
    float imposto1 = comDesconto1 * 0.18f;
    float total1 = comDesconto1 + imposto1;
    printf("Total 1: R$ %.2f\n", total1);

    // Produto 2
    float subtotal2 = 45.00f * 2;
    float desconto2 = subtotal2 * (5.0f / 100);
    float comDesconto2 = subtotal2 - desconto2;
    float imposto2 = comDesconto2 * 0.18f; // e se alguém digitar 0.19 aqui por engano?
    float total2 = comDesconto2 + imposto2;
    printf("Total 2: R$ %.2f\n", total2);

    // Produto 3... o mesmo bloco de novo
}

O problema não é só a repetição visual. É que a mesma regra de negócio (calcular imposto, aplicar desconto) está copiada em vários lugares. Se a alíquota de ICMS mudar, ou se alguém digitar 0.19 em vez de 0.18 em uma única cópia — como no comentário acima — o programa passa a calcular valores diferentes para produtos diferentes, sem nenhum erro de compilação avisando.

Uma subrotina (ou função) resolve isso: a lógica é escrita uma única vez, testada uma única vez, e reutilizada quantas vezes for preciso.

float calcularTotalComImposto(float preco, int quantidade, float percentualDesconto);

int main(void) {
    float total1 = calcularTotalComImposto(89.90f, 3, 10.0f);
    printf("Total 1: R$ %.2f\n", total1);

    float total2 = calcularTotalComImposto(45.00f, 2, 5.0f);
    printf("Total 2: R$ %.2f\n", total2);
}

A partir de agora, esse será o exemplo usado ao longo de todo o roteiro: uma calculadora de nota fiscal simplificada, com subtotal, desconto e imposto.

Ideia central

Modularizar não é sobre escrever menos linhas — é sobre ter um único lugar para corrigir e manter cada regra do programa.

Protótipo, definição e chamada

Toda função em C aparece de três formas diferentes no código-fonte, e é comum confundir uma com a outra no início. Vamos separar a assinatura da função calcularTotalComImposto em suas partes:

Sem o protótipo, o compilador só saberia da existência de calcularTotalComImposto ao chegar na sua definição — e como ela está depois do main, a chamada dentro do main seria um erro. É por isso que protótipos existem: eles deixam o contrato da função visível antes de qualquer chamada.

Funções void x funções com retorno tipado

Nem toda função existe para calcular um valor. Algumas existem para fazer algo — como imprimir um recibo — e não precisam devolver nada ao ponto onde foram chamadas. Para essas, usamos o tipo void:

void imprimirRecibo(float total) {
    printf("Total a pagar: R$ %.2f\n", total);
}

Já calcularTotalComImposto precisa devolver o valor calculado, para que o restante do programa possa usá-lo — por isso seu tipo de retorno é float, e seu corpo termina com return:

float calcularTotalComImposto(float preco, int quantidade, float percentualDesconto) {
    // ...cálculo do subtotal, desconto e imposto...
    return comDesconto + imposto;
}

As duas trabalham juntas na prática:

int main(void) {
    float total = calcularTotalComImposto(89.90f, 3, 10.0f); // calcula e devolve um valor
    imprimirRecibo(total);                                    // só executa uma ação, não devolve nada
}

Regra prática: se, depois de escrever a função, você sentir necessidade de usar o resultado dela em outra expressão ou variável, ela precisa de um tipo de retorno. Se ela só produz um efeito (imprimir, gravar, exibir), void é suficiente.

Parâmetros e passagem por valor

Em C, quando você passa um argumento para uma função, a função recebe uma cópia do valor — não a variável original. Isso tem uma consequência que costuma surpreender no início. Considere esta tentativa de aplicar um desconto:

void tentarAplicarDesconto(float preco) {
    preco = preco - (preco * 0.10f); // altera só a cópia local
}

int main(void) {
    float precoProduto = 89.90f;
    tentarAplicarDesconto(precoProduto);
    printf("Preco: R$ %.2f\n", precoProduto); // imprime 89.90 — sem desconto!
}

Mesmo depois da chamada, precoProduto continua valendo 89.90. A função alterou apenas sua própria cópia, chamada também de preco, que existe num espaço de memória diferente do precoProduto de main.

Para que o desconto realmente "volte" para quem chamou, a função precisa devolver o novo valor pelo return, e quem chamou precisa guardar esse retorno:

float aplicarDesconto(float preco, float percentual) {
    return preco - (preco * percentual / 100);
}

int main(void) {
    float precoProduto = 89.90f;
    precoProduto = aplicarDesconto(precoProduto, 10.0f); // agora sim: 80.91
    printf("Preco: R$ %.2f\n", precoProduto);
}
Olhando à frente

Na Semana 2 veremos como alterar diretamente a variável do chamador usando ponteiros (passagem por referência) — útil quando uma função precisa modificar mais de um valor ao mesmo tempo. Por enquanto, o caminho é sempre: calcular e return.

Escopo de variáveis: locais e globais

A alíquota de ICMS usada em calcularImposto não muda de uma chamada para outra — é uma regra fixa do sistema inteiro. Faz sentido declará-la fora de qualquer função, como uma variável global:

const float ALIQUOTA_ICMS = 0.18f; // global: visível em todo o arquivo

float calcularImposto(float valor) {
    float imposto = valor * ALIQUOTA_ICMS; // local: só existe aqui dentro
    return imposto;
}

float calcularSubtotal(float preco, int quantidade) {
    float subtotal = preco * quantidade; // local: outra variável, outro espaço
    return subtotal;
}
Cuidado

Variáveis globais parecem convenientes, mas qualquer função pode alterá-las a qualquer momento — o que torna o comportamento do programa mais difícil de rastrear. Reserve-as para valores realmente fixos e amplamente compartilhados, como uma alíquota de imposto. Para dados que mudam durante o processamento, prefira parâmetros e retornos.

Pilha de execução

Quando main chama calcularTotalComImposto, e esta por sua vez chama calcularSubtotal, aplicarDesconto e calcularImposto, o computador precisa lembrar onde cada função deve "voltar" quando terminar. Ele faz isso empilhando um quadro (frame) para cada chamada ativa — a chamada mais recente sempre fica no topo.

float calcularTotalComImposto(float preco, int quantidade, float percentualDesconto) {
    float subtotal    = calcularSubtotal(preco, quantidade);
    float comDesconto = aplicarDesconto(subtotal, percentualDesconto);
    float imposto     = calcularImposto(comDesconto);
    return comDesconto + imposto;
}

Isso explica, por exemplo, por que a variável subtotal de calcularSubtotal deixa de existir assim que a função retorna: seu quadro foi desempilhado, e a memória que ele ocupava está livre para o próximo quadro que for empilhado.

Funções aplicadas a problemas reais

Os mesmos três elementos — protótipo, definição, chamada — e a mesma regra de passagem por valor valem para qualquer função, não só para cálculos financeiros. Alguns exemplos com aplicação direta:

Área de um terreno

Usada em orçamentos de construção e imobiliárias para calcular área construída ou de lote.

calcularAreaRetangular(12.5, 8.0) → 100.0 m²

Conversão de temperatura

Necessária sempre que dados de sensores ou previsões do tempo vêm em uma escala diferente da usada localmente.

celsiusParaFahrenheit(28.0) → 82.4 °F

Divisão de turno por paridade

Em um estoque, pedidos de número par podem ser conferidos pelo turno da manhã e ímpares pelo da tarde — uma forma simples de balancear carga de trabalho.

turnoDeConferencia(4128) → turno da manhã

float calcularAreaRetangular(float base, float altura) {
    return base * altura;
}

float celsiusParaFahrenheit(float celsius) {
    return celsius * 9.0f / 5.0f + 32;
}

int turnoDeConferencia(int numeroPedido) {
    if (numeroPedido % 2 == 0) {
        return 1; // turno da manhã
    }
    return 2;     // turno da tarde
}

Repare que as três seguem exatamente a mesma estrutura discutida na Aula 1: um tipo de retorno compatível com o que a função calcula, parâmetros que representam os dados de entrada, e um return que devolve o resultado — nada disso muda em função do domínio do problema.

Programas com múltiplas funções e depuração

Juntando tudo, o programa da nota fiscal fica assim, com cada responsabilidade isolada em sua própria função:

#include <stdio.h>

const float ALIQUOTA_ICMS = 0.18f;

float calcularSubtotal(float preco, int quantidade);
float aplicarDesconto(float subtotal, float percentualDesconto);
float calcularImposto(float valor);
float calcularTotalComImposto(float preco, int quantidade, float percentualDesconto);
void imprimirRecibo(float total);

int main(void) {
    float preco = 89.90f;
    int quantidade = 3;
    float percentualDesconto = 10.0f;

    float total = calcularTotalComImposto(preco, quantidade, percentualDesconto);
    imprimirRecibo(total);

    return 0;
}

float calcularTotalComImposto(float preco, int quantidade, float percentualDesconto) {
    float subtotal = calcularSubtotal(preco, quantidade);
    printf("[DEBUG] subtotal = %.2f\n", subtotal);

    float comDesconto = aplicarDesconto(subtotal, percentualDesconto);
    printf("[DEBUG] comDesconto = %.2f\n", comDesconto);

    float imposto = calcularImposto(comDesconto);
    printf("[DEBUG] imposto = %.2f\n", imposto);

    return comDesconto + imposto;
}

float calcularSubtotal(float preco, int quantidade) {
    return preco * quantidade;
}

float aplicarDesconto(float subtotal, float percentualDesconto) {
    float desconto = subtotal * (percentualDesconto / 100);
    return subtotal - desconto;
}

float calcularImposto(float valor) {
    return valor * ALIQUOTA_ICMS;
}

void imprimirRecibo(float total) {
    printf("Total a pagar: R$ %.2f\n", total);
}

Lendo o rastro de printf

As linhas marcadas com [DEBUG] não fazem parte do resultado final do programa — servem só para acompanhar, em cada etapa, o valor que está sendo empilhado e desempilhado, exatamente como na Figura 5:

[DEBUG] subtotal = 269.70
[DEBUG] comDesconto = 242.73
[DEBUG] imposto = 43.69
Total a pagar: R$ 286.42

Essa técnica — imprimir valores intermediários com printf — é a forma mais simples de depuração: se o total final estiver errado, o rastro mostra exatamente em qual função o valor já saiu do esperado, sem precisar adivinhar o que aconteceu dentro da pilha de chamadas.
