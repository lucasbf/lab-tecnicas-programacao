Passagem por Referência em C
ponteiros, vetores, matrizes e strings em funções

Uma função com return só devolve um resultado por vez. Mas e quando um problema — como encontrar as duas raízes de uma equação do 2º grau — exige dois resultados ao mesmo tempo? Este roteiro usa ponteiros para escrever diretamente nas variáveis de quem chamou a função, e mostra por que vetores, matrizes e strings já se comportam assim por padrão em C.

main() → calcularRaizes(&x1, &x2)

O problema dos dois retornos

Uma equação do 2º grau, ax² + bx + c = 0, é resolvida pela fórmula de Bhaskara e produz duas raízes, x1 e x2. Uma primeira tentativa de escrever isso como função, usando o que já conhecemos da Semana 1, esbarra logo de cara:

float calcularRaiz(float a, float b, float c) {
    float delta = b * b - 4 * a * c;
    float raizDelta = sqrt(delta);
    float x1 = (-b + raizDelta) / (2 * a);
    float x2 = (-b - raizDelta) / (2 * a); // calculado...
    return x1; // ...mas como devolver x2 também?
}

x2 é calculado corretamente, mas return só devolve um valor por chamada — assim que a função termina, o quadro dela é desempilhado (como vimos na Semana 1) e x2 desaparece junto com ele. Não existe return x1, x2; em C.

Olhando para trás

Na Semana 1 prometemos: "veremos como alterar diretamente a variável do chamador usando ponteiros — útil quando uma função precisa modificar mais de um valor ao mesmo tempo". É exatamente isso que este roteiro resolve, começando pelo próprio conceito de ponteiro.

Ponteiros: endereços, & e *

Toda variável em C mora em algum endereço de memória. Normalmente não precisamos pensar nisso — mas um ponteiro é justamente uma variável cujo valor é um endereço, e não um número comum. Ele "aponta para" outra variável.

  • &x — operador endereço-de: devolve o endereço de memória onde x está guardada.
  • float *p; — declara p como um ponteiro para float: ele vai guardar o endereço de uma variável do tipo float, não um float diretamente.
  • *p — operador de indireção (ou dereferência): acessa o valor que está no endereço guardado por p. Pode ser lido (y = *p;) ou escrito (*p = 10;).
int x = 5;      // uma variável comum
int *p = &x;   // p guarda o endereço de x
*p = 10;        // escreve 10 no endereço que p guarda — ou seja, em x
Dois usos do mesmo símbolo

* significa coisas diferentes dependendo de onde aparece: em float *p (numa declaração), ele diz "p é um ponteiro". Em *p = 10 (fora de declaração), ele diz "acesse o que está no endereço guardado por p". É comum confundir os dois no início — preste atenção ao contexto.

Ponteiros como parâmetros

Voltando ao problema da Seção 1: para que calcularRaizes escreva os dois resultados diretamente nas variáveis do chamador, seus dois últimos parâmetros precisam ser ponteiros — float *x1 e float *x2 — em vez de float comuns:

A função completa e sua chamada:

void calcularRaizes(float a, float b, float c, float *x1, float *x2) {
    float delta = b * b - 4 * a * c;
    float raizDelta = sqrt(delta);
    *x1 = (-b + raizDelta) / (2 * a);
    *x2 = (-b - raizDelta) / (2 * a);
}

int main(void) {
    float x1, x2;
    calcularRaizes(1, -5, 6, &x1, &x2); // x² - 5x + 6 = 0
    printf("x1 = %.2f, x2 = %.2f\n", x1, x2); // x1 = 3.00, x2 = 2.00
    return 0;
}

Repare que, dentro de main, x1 e x2 são float comuns — quem os transforma em ponteiros é a chamada, com &x1 e &x2. Dentro de calcularRaizes, x1 e x2 já chegam como ponteiros, por isso o corpo da função usa *x1 e *x2 para escrever os resultados.

Por que trocar valores sem ponteiro não funciona

O exemplo clássico para fixar passagem por referência é uma função que troca o conteúdo de duas variáveis. A primeira tentativa, sem ponteiros, repete o mesmo erro da passagem por valor visto na Semana 1:

void trocar(int a, int b) {
    int temp = a;
    a = b;
    b = temp;
}

int main(void) {
    int x = 5, y = 10;
    trocar(x, y);
    printf("x = %d, y = %d\n", x, y); // x = 5, y = 10 — nada mudou!
}

A correção troca os parâmetros por ponteiros — a e b passam a guardar os endereços de x e y, em vez de cópias dos seus valores:

void trocar(int *a, int *b) {
    int temp = *a;
    *a = *b;
    *b = temp;
}

int main(void) {
    int x = 5, y = 10;
    trocar(&x, &y);
    printf("x = %d, y = %d\n", x, y); // x = 10, y = 5
}

Verifique seu entendimento — Aula 5 — confira as respostas no Gabarito, seção 10

  1. Por que void trocar(int a, int b), sem ponteiros, não troca x e y em main?

    1. Porque a função tem um erro de sintaxe
    2. a e b recebem cópias dos valores, em endereços diferentes de x e y
    3. Porque int não pode ser trocado, só float
    4. Porque falta um return no final da função

  2. O que o operador & faz quando escrito antes do nome de uma variável, como em &x?

    1. Multiplica o valor de x por dois
    2. Devolve o endereço de memória onde x está guardada
    3. Cria uma cópia de x com outro nome
    4. Converte x para ponteiro permanentemente

  3. Em float *x1, dentro de uma declaração de parâmetro, o que o * indica?

    1. Que x1 vai receber vários valores float ao mesmo tempo
    2. Que x1 é um ponteiro para float — guarda um endereço, não um float comum
    3. Que x1 é opcional na chamada da função
    4. Que o valor de x1 será multiplicado dentro da função

  4. Já em *a = *b;, fora de uma declaração, o que cada * faz?

    1. Declara a e b como ponteiros pela segunda vez
    2. Acessa (lê ou escreve) o valor guardado no endereço para o qual o ponteiro aponta
    3. Compara se a e b apontam para o mesmo endereço
    4. Multiplica os valores apontados por a e por b

Arrays "decaem" para ponteiros

Ponteiros como parâmetro exigem & na chamada porque int, float e char sozinhos são, por padrão, passados por valor. Vetores, matrizes e strings são diferentes: eles já são passados por referência automaticamente, sem precisar de &.

Quando um vetor é passado como argumento, C não copia seus elementos — ele passa apenas o endereço da primeira posição. Isso é chamado de o vetor "decair" para ponteiro:

void imprimirNotas(int notas[], int tamanho) {
    for (int i = 0; i < tamanho; i++) {
        printf("%d ", notas[i]);
    }
}
// equivalente a: void imprimirNotas(int *notas, int tamanho)

Como não há cópia, uma função que altera os elementos do vetor altera o vetor original do chamador — sem precisar de & nem de ponteiro explícito na assinatura:

void aplicarBonus(int notas[], int tamanho, int bonus) {
    for (int i = 0; i < tamanho; i++) {
        notas[i] = notas[i] + bonus;
    }
}

int main(void) {
    int notas[5] = {6, 7, 5, 8, 6};
    aplicarBonus(notas, 5, 1); // sem & — vetores já vão por referência
    // notas agora é {7, 8, 6, 9, 7} no próprio main
}
Pegadinha comum

Dentro da função, sizeof(notas) não devolve o tamanho do vetor original — devolve o tamanho de um ponteiro (geralmente 8 bytes), porque, decaído, notas é só um endereço. É exatamente por isso que o tamanho do vetor precisa ser passado como parâmetro extra, como em aplicarBonus(notas, 5, 1): a função não tem como descobrir sozinha onde o vetor termina.

Strings são arrays: alterando em vigor

Uma string em C é um vetor de char terminado em \0. Como todo vetor, ela decai para ponteiro ao ser passada — então uma função que recebe char texto[] pode alterar a string original, caractere por caractere:

void paraMaiusculas(char texto[]) {
    for (int i = 0; texto[i] != '\0'; i++) {
        if (texto[i] >= 'a' && texto[i] <= 'z') {
            texto[i] = texto[i] - 32; // distância entre 'a' e 'A' na tabela ASCII
        }
    }
}

int main(void) {
    char nome[] = "maria";
    paraMaiusculas(nome); // sem & — char[] também decai para ponteiro
    printf("%s\n", nome); // MARIA
}

Matrizes como parâmetros

Uma matriz é um vetor de vetores, e também decai para ponteiro ao ser passada como parâmetro. A única exigência extra é que o compilador precisa saber o número de colunas para calcular o endereço de cada matriz[i][j] — por isso ele é fixado na assinatura:

void somarLinha(int matriz[][3], int linha, int *soma) {
    *soma = 0;
    for (int j = 0; j < 3; j++) {
        *soma += matriz[linha][j];
    }
}

int main(void) {
    int notas[2][3] = { {7, 8, 6}, {9, 5, 10} };
    int total;
    somarLinha(notas, 0, &total); // notas sem & (decai), total com & (é int comum)
    printf("Soma da linha 0: %d\n", total); // 21
}
Resumindo a regra

Vetores, matrizes e strings são sempre passados por referência em C — automaticamente, sem &. Só variáveis "simples" (int, float, char isolados) precisam de um ponteiro explícito (* na assinatura, & na chamada) quando a função precisa alterá-las.

Verifique seu entendimento — Aula 6 — confira as respostas no Gabarito, seção 10

  1. Ao passar int notas[5] para uma função, o que é efetivamente copiado?

    1. Os 5 valores inteiros, um por um
    2. Apenas o endereço da primeira posição do vetor
    3. Nada — a função não recebe informação alguma sobre o vetor
    4. O vetor inteiro mais um índice extra

  2. Por que é preciso passar o tamanho do vetor como parâmetro extra, como em aplicarBonus(notas, 5, 1)?

    1. Por exigência do compilador, sem relação com como o vetor é armazenado
    2. Porque o vetor decaiu para ponteiro, e um ponteiro não sabe quantos elementos existem depois dele
    3. Porque vetores em C sempre têm exatamente 5 posições
    4. Só é necessário para vetores de float, não de int

  3. void paraMaiusculas(char texto[]) consegue alterar a string original em main porque:

    1. Toda função void tem permissão especial para alterar variáveis externas
    2. char texto[] também decai para ponteiro — a função recebe o endereço do vetor original
    3. O compilador copia o texto de volta para main automaticamente ao final
    4. Strings não seguem a mesma regra de vetores comuns

  4. Em int matriz[][3], por que o número de colunas (3) precisa ser fixo na assinatura?

    1. Por padrão de estilo, mas o programa funcionaria igual sem isso
    2. O compilador precisa saber quantos elementos pular por linha para calcular o endereço de matriz[i][j]
    3. Porque matrizes em C só podem ter 3 colunas
    4. Para reservar espaço extra de memória, caso a matriz cresça

Simulação passo a passo: trocando dois valores

Vamos acompanhar, instrução por instrução, exatamente o que acontece na memória durante esta execução:

#include <stdio.h>

void trocar(int *a, int *b) {
    int temp = *a;
    *a = *b;
    *b = temp;
}

int main(void) {
    int x = 5, y = 10;
    printf("Antes:  x = %d, y = %d\n", x, y);
    trocar(&x, &y);
    printf("Depois: x = %d, y = %d\n", x, y);
    return 0;
}
Passo Instrução executada x (main) y (main) a (trocar) b (trocar) temp (trocar)
1 int x = 5, y = 10; 510———
2 trocar(&x, &y); — chamada; um novo quadro é empilhado 510 endereço x endereço y —
3 int temp = *a; — lê o valor no endereço de a 510 endereço xendereço y 5
4 *a = *b; — escreve o valor de *b (10) no endereço de a 1010 endereço xendereço y 5
5 *b = temp; — escreve temp (5) no endereço de b 105 endereço xendereço y 5
6 trocar retorna — o quadro é desempilhado 105 (não existe mais) (não existe mais) (não existe mais)
7 segundo printf em main → "Depois: x = 10, y = 5" 105———

Repare no que muda em cada coluna: a e b nunca guardam um número "comum" como 5 ou 10 — eles guardam endereços, e continuam apontando para x e y do início ao fim. Já x e y só mudam nos passos 4 e 5, exatamente quando o corpo de trocar escreve através de *a e *b — nunca em nenhuma outra linha, e sem que main apareça em nenhuma dessas duas linhas de código.

Exercícios aplicados: busca, soma/média, inverter string

Os mesmos dois recursos — vetores passados por referência e ponteiros para "retornos extras" — resolvem a maioria dos exercícios clássicos de laboratório:

Busca em vetor

Percorre o vetor procurando um valor; devolve a posição encontrada, ou -1 se não existir.

buscarValor(notas, 5, 8) → 3

Soma e média

Soma pode ser calculada com return simples; se a função precisar devolver soma e média juntas, um dos dois vira parâmetro por referência.

calcularMedia(notas, 5) → 6.40

Inverter string

Troca caracteres das pontas para o centro, exatamente com a mesma lógica de trocar — só que dentro de um laço.

inverterString("maria") → "airam"

int buscarValor(int vetor[], int tamanho, int alvo) {
    for (int i = 0; i < tamanho; i++) {
        if (vetor[i] == alvo) {
            return i;
        }
    }
    return -1; // não encontrado
}

float calcularMedia(int vetor[], int tamanho) {
    int soma = 0;
    for (int i = 0; i < tamanho; i++) {
        soma += vetor[i];
    }
    return (float) soma / tamanho;
}

void inverterString(char texto[], int tamanho) {
    int inicio = 0;
    int fim = tamanho - 1;
    while (inicio < fim) {
        char temp = texto[inicio]; // mesma técnica de trocar()
        texto[inicio] = texto[fim];
        texto[fim] = temp;
        inicio++;
        fim--;
    }
}

inverterString não precisa de & nem de return: como char texto[] já é uma referência ao vetor original, cada troca de caracteres altera a string do chamador diretamente — o mesmo princípio das Seções 4 e 6, agora dentro de um laço que caminha das duas pontas para o centro.

  1. Na tabela de simulação, por que a e b nunca aparecem com um valor "comum" como 5 ou 10?

    1. Porque são declarados como float, não como int
    2. Porque são ponteiros — guardam endereços de x e y, não os números em si
    3. Porque a função trocar tem um erro de lógica
    4. Porque main nunca inicializa x e y corretamente

  2. No passo 4 da simulação (*a = *b;), o valor de x muda em main mesmo sem essa linha mencionar main. Por quê?

    1. Porque C sincroniza automaticamente todas as variáveis chamadas x
    2. Porque a guarda o endereço de x, e *a = ...; escreve exatamente nesse endereço
    3. Porque a variável x é global no programa
    4. O valor de x só muda depois que a função retorna, não durante

  3. Uma função float calcularMedia(int vetor[], int tamanho) poderia, tecnicamente, alterar os valores originais do vetor?

    1. Não, porque vetor[] é sempre somente-leitura dentro da função
    2. Sim — o vetor chega por referência, então nada impede a escrita; é só uma convenção não fazer isso numa função de "cálculo"
    3. Só se a função for declarada como void
    4. Não, porque tamanho bloqueia qualquer escrita no vetor

Aula 5 — Passagem por referência

  1. 1. b) a e b recebem cópias dos valores, em endereços diferentes de x e y— é a mesma passagem por valor da Semana 1: a e b são variáveis locais à função, completamente separadas de x e y — trocá-las não alcança o chamador.
  2. 2. b) Devolve o endereço de memória onde x está guardada— & é o operador endereço-de: &x não é um valor comum, é a posição de memória onde x mora — é isso que se passa para um parâmetro ponteiro.
  3. 3. b) Que x1 é um ponteiro para float — guarda um endereço, não um float comum— na declaração, * marca o tipo como ponteiro. float *x1 lê-se "x1 é um ponteiro para float".
  4. 4. b) Acessa (lê ou escreve) o valor guardado no endereço para o qual o ponteiro aponta— fora de uma declaração, * é o operador de indireção: *a lê o valor no endereço guardado por a; usado à esquerda de =, escreve nesse mesmo endereço.

Aula 6 — Arrays e strings como parâmetros

  1. 1. b) Apenas o endereço da primeira posição do vetor— um vetor decai para ponteiro: a função recebe o endereço do elemento 0 e acessa os demais a partir dele, sem nenhuma cópia dos 5 valores.
  2. 2. b) Porque o vetor decaiu para ponteiro, e um ponteiro não sabe quantos elementos existem depois dele— sem o tamanho, a função só teria um endereço de início — sizeof dentro dela mede o ponteiro, não o vetor, então não há como descobrir onde ele termina.
  3. 3. b) char texto[] também decai para ponteiro — a função recebe o endereço do vetor original— uma string é um vetor de char — a mesma regra de decaimento para ponteiro se aplica, por isso alterar texto[i] dentro da função altera o vetor original.
  4. 4. b) O compilador precisa saber quantos elementos pular por linha para calcular o endereço de matriz[i][j]— uma matriz é armazenada como uma sequência contínua de linhas; sem saber o tamanho de cada linha, o compilador não consegue calcular onde a linha i começa.

Aulas 7 e 8 — Prática em laboratório

  1. 1. b) Porque são ponteiros — guardam endereços de x e y, não os números em si— a e b são int*, então o que eles guardam é sempre um endereço de memória — os valores 5 e 10 aparecem indiretamente, através de *a e *b.
  2. 2. b) Porque a guarda o endereço de x, e *a = ...; escreve exatamente nesse endereço— a escrita acontece no endereço guardado por a, que é o endereço de x — por isso o efeito aparece em main imediatamente, ainda durante a chamada.
  3. 3. b) Sim — o vetor chega por referência, então nada impede a escrita; é só uma convenção não fazer isso numa função de "cálculo"— tecnicamente sim: vetor[] é o mesmo vetor do chamador. Nada no C impede a escrita — evitar alterar dados de entrada numa função que só deveria calcular é uma boa prática, não uma regra da linguagem.
