Memória volátil e o que é um arquivo

Todos os programas que escrevemos até agora têm algo em comum: quando o programa termina, os dados desaparecem. Variáveis, vetores, structs e até a memória obtida com malloc vivem na memória principal (RAM), que é volátil: só guarda informação enquanto o programa está em execução.

Para que uma informação sobreviva ao fim do programa, ela precisa ir para a memória secundária (SSD, disco rígido, pen drive), que é não volátil. A forma de organizar dados ali é o arquivo.

Arquivo: conjunto de dados armazenado em memória secundária, identificado por um nome, que persiste independentemente da execução do programa que o criou.

Memória principal (RAM)Memória secundária (SSD/HD)
Volátil?SimNão
VelocidadeMuito rápidaBem mais lenta
CapacidadeMenor (GB)Maior (centenas de GB, TB)
Em C, acessamos porvariáveis, ponteirosarquivos (FILE *)

A problemática e o armazenamento físico

O cadastro que some

Na Unidade V construímos um cadastro de alunos com structs. Funciona bem… até fecharmos o programa. Na próxima execução o vetor está vazio e o usuário precisa digitar tudo de novo.

Dados que vêm de fora

Muitas vezes os dados já existem e foram produzidos por outro programa: uma planilha exportada em CSV, o log de um servidor, os resultados de um campeonato, as leituras de um sensor. Digitá-los no teclado não é opção: o programa precisa ler o arquivo.

Princípios do armazenamento físico

Para o sistema operacional, um arquivo é apenas uma sequência de bytes. O que esses bytes significam depende de como foram gravados:

Arquivo texto

Os bytes são caracteres legíveis (ASCII/UTF-8), organizados em linhas terminadas por '\n'. Abre em qualquer editor.

.txt · .csv · .c · .html

Arquivo binário

Os bytes são uma cópia direta da memória: o mesmo padrão de bits que a variável tem na RAM. Não é legível em um editor de texto.

.exe · .png · .mp3 · .dat

O tipo FILE e o ciclo de vida

As funções de arquivo estão em <stdio.h>, a mesma biblioteca do printf e do scanf. Um arquivo aberto é representado por um ponteiro para o tipo FILE:

FILE *arq;

FILE é uma struct definida pela biblioteca que guarda o estado do arquivo aberto: a posição atual, o buffer, os indicadores de erro e de fim de arquivo. Nunca acessamos seus atributos diretamente; apenas passamos o ponteiro para as funções.

fopen, modos de abertura e fclose

FILE *fopen(const char *nome_arquivo, const char *modo);
  • nome_arquivo: o caminho do arquivo. Se for só o nome ("alunos.txt"), ele é procurado na pasta onde o programa está sendo executado.
  • modo: string que diz o que pretendemos fazer com o arquivo.
  • Retorna um ponteiro para FILE ou NULL se não conseguir abrir.
ModoSignificadoSe o arquivo existeSe não existe
"r"leitura (read)lê desde o inícioretorna NULL
"w"escrita (write)apaga todo o conteúdocria
"a"acréscimo (append)escreve no finalcria
"r+"leitura e escritalê/escreve desde o inícioretorna NULL
"w+"leitura e escritaapaga todo o conteúdocria
"a+"leitura e acréscimolê de qualquer ponto, escreve no finalcria

Acrescentando a letra b ao modo ("rb", "wb", "ab", "r+b"…) o arquivo é aberto em modo binário. Sem o b, em modo texto.

Cuidado com o "w"

Abrir um arquivo existente em modo "w" destrói o conteúdo anterior, sem perguntar. Para adicionar dados a um arquivo, use "a".

Verificando e fechando

#include <stdio.h>

int main(void) {
    FILE *arq = fopen("dados.txt", "r");

    if (arq == NULL) {
        printf("Erro ao abrir o arquivo!\n");
        return 1;
    }

    // ... usa o arquivo ...

    fclose(arq);
    return 0;
}
  • Sempre teste o retorno do fopen. Usar um FILE * nulo trava o programa, exatamente como desreferenciar um ponteiro NULL (Unidade IV).
  • fclose descarrega o buffer (as escritas ficam acumuladas na memória e vão para o disco em blocos) e libera o arquivo. Esquecer o fclose pode fazer com que parte dos dados nunca seja gravada.
Dica: Dev-C++ e Code::Blocks

Se o fopen retorna NULL para um arquivo que "está ali", confira se ele está na mesma pasta do executável (no Code::Blocks, na pasta do projeto).

As "primas" de printf e scanf

As funções de arquivo texto são parentes próximas das funções de teclado e tela que já conhecemos. A diferença é um parâmetro a mais: o FILE * que indica qual arquivo usar.

Teclado / telaArquivoFunção
putchar(c)fputc(c, arq)escreve um caractere
getchar()fgetc(arq)lê um caractere
printf(…)fprintf(arq, …)escrita formatada
scanf(…)fscanf(arq, …)leitura formatada
puts(s)fputs(s, arq)escreve uma string
fgets(s, n, stdin)fgets(s, n, arq)lê uma linha
Curiosidade

O teclado e a tela também são FILE *: stdin e stdout. printf(…) é o mesmo que fprintf(stdout, …). É por isso que já usávamos fgets(s, n, stdin) na Unidade II.

Escrevendo: fprintf e o modo "a"

#include <stdio.h>

int main(void) {
    FILE *arq = fopen("tabuada.txt", "w");
    if (arq == NULL) {
        printf("Erro ao criar o arquivo!\n");
        return 1;
    }

    for (int i = 1; i <= 10; i++)
        fprintf(arq, "7 x %2d = %2d\n", i, 7 * i);

    fclose(arq);
    printf("Arquivo tabuada.txt gerado.\n");
    return 0;
}

Execute e abra tabuada.txt em um editor: o conteúdo é exatamente o que apareceria na tela com printf.

Acrescentando: modo "a"

FILE *log = fopen("log.txt", "a");
if (log != NULL) {
    fprintf(log, "Programa executado com sucesso.\n");
    fclose(log);
}

Execute três vezes e o arquivo terá três linhas. Com "w", teria sempre uma.

Lendo: fgetc, fgets e fscanf

Caractere a caractere: fgetc e EOF

fgetc devolve o próximo caractere do arquivo ou a constante EOF (End Of File, normalmente -1) quando o arquivo acabou. Por isso o retorno deve ser guardado em um int, e não em um char:

#include <stdio.h>

int main(void) {
    FILE *arq = fopen("tabuada.txt", "r");
    if (arq == NULL) {
        printf("Erro ao abrir o arquivo!\n");
        return 1;
    }

    int c, linhas = 0;
    while ((c = fgetc(arq)) != EOF) {
        putchar(c);
        if (c == '\n')
            linhas++;
    }

    fclose(arq);
    printf("\nO arquivo tem %d linhas.\n", linhas);
    return 0;
}

Linha a linha: fgets

char linha[100];

while (fgets(linha, sizeof(linha), arq) != NULL) {
    printf("> %s", linha);
}
  • fgets lê até encontrar um '\n', até ler n - 1 caracteres ou até o fim do arquivo, o que vier primeiro.
  • O '\n' fica dentro da string. Como na Unidade II, linha[strcspn(linha, "\n")] = '\0'; o remove.
  • Retorna NULL quando não há mais nada para ler.

Leitura formatada: fscanf

fscanf funciona como o scanf e retorna quantos itens conseguiu ler, ou EOF se o arquivo terminou antes de ler qualquer coisa. Considere o arquivo notas.txt:

842250 7.5 8.0
844557 5.0 6.5
845160 9.0 9.5
int ra;
float n1, n2;

while (fscanf(arq, "%d %f %f", &ra, &n1, &n2) == 3) {
    printf("RA %d - média %.2f\n", ra, (n1 + n2) / 2);
}

Comparar com == 3 (o número de itens esperado) é mais seguro do que comparar com != EOF: se uma linha estiver mal formatada, o laço para em vez de entrar em loop infinito.

Armadilha clássica: while (!feof(arq))

A função feof só fica verdadeira depois que uma leitura já falhou por chegar ao fim. Por isso o laço da esquerda processa a última linha duas vezes:

✗ Evite 
while (!feof(arq)) {
    fscanf(arq, "%d %f %f", &ra, &n1, &n2);
    printf("%d\n", ra);
}
// imprime 845160 duas vezes
✓ Prefira 
while (fscanf(arq, "%d %f %f",
              &ra, &n1, &n2) == 3) {
    printf("%d\n", ra);
}
// o laço para na leitura que falha

Regra prática: controle o laço pelo retorno da função de leitura.

Arquivos CSV + structs

O formato CSV (Comma-Separated Values) é um arquivo texto em que cada linha é um registro e os campos são separados por um delimitador: , ou, no Brasil, ;, já que a vírgula é o separador decimal. É o formato que Excel e Google Sheets exportam. Juntando com a Unidade V, cada linha do CSV vira uma struct.

alunos.csv:

RA;Nome;Nota
842250;Ana Beatriz Lima;8.5
844557;Bruno Henrique Souza;7.8
845160;Carla Mendes Oliveira;5.1
#include <stdio.h>

#define MAX 100

typedef struct {
    int   ra;
    char  nome[50];
    float nota;
} Aluno;

int main(void) {
    FILE *arq = fopen("alunos.csv", "r");
    if (arq == NULL) {
        printf("Erro ao abrir alunos.csv\n");
        return 1;
    }

    Aluno vet[MAX];
    int n = 0;
    char cabecalho[100];

    fgets(cabecalho, sizeof(cabecalho), arq);   // descarta a 1a linha

    while (n < MAX &&
           fscanf(arq, "%d;%49[^;];%f\n", &vet[n].ra, vet[n].nome, &vet[n].nota) == 3) {
        n++;
    }
    fclose(arq);

    FILE *saida = fopen("aprovados.csv", "w");
    if (saida == NULL) {
        printf("Erro ao criar aprovados.csv\n");
        return 1;
    }
    fprintf(saida, "RA;Nome;Nota\n");
    for (int i = 0; i < n; i++)
        if (vet[i].nota >= 6.0)
            fprintf(saida, "%d;%s;%.1f\n", vet[i].ra, vet[i].nome, vet[i].nota);
    fclose(saida);

    printf("%d alunos lidos.\n", n);
    return 0;
}
Lendo campos com espaços

O especificador %49[^;] significa "leia até 49 caracteres que não sejam ;". É assim que lemos um nome com espaços até o próximo separador. O \n no final do formato consome a quebra de linha.

fwrite, fread e o cadastro persistente

No modo binário não há conversão para texto: os bytes da memória são copiados como estão para o arquivo, e vice-versa. As vantagens:

  • Simplicidade: uma struct inteira, ou um vetor inteiro de structs, é gravada com um único comando.
  • Tamanho fixo: todo registro ocupa exatamente sizeof(tipo) bytes, o que permite acesso aleatório.
  • Velocidade: não há conversão de números para dígitos e de volta.

A desvantagem: o arquivo não é legível por pessoas e pode não ser portável entre computadores ou compiladores diferentes (tamanho dos tipos, ordem dos bytes, alinhamento das structs).

Escrevendo: fwrite

size_t fwrite(const void *origem, size_t tamanho, size_t quantidade, FILE *arq);

Grava quantidade elementos de tamanho bytes cada, a partir do endereço origem, e retorna quantos elementos foram efetivamente gravados.

Aluno a = {842250, "Ana Beatriz Lima", 8.5};
Aluno turma[40];

fwrite(&a, sizeof(Aluno), 1, arq);        // uma struct
fwrite(turma, sizeof(Aluno), 40, arq);    // o vetor inteiro

Repare no void * (Unidade IV): fwrite aceita o endereço de qualquer tipo, porque só enxerga bytes.

Lendo: fread

size_t fread(void *destino, size_t tamanho, size_t quantidade, FILE *arq);

Mesma ideia, no sentido contrário. Retorna quantos elementos conseguiu ler, o que é perfeito para controlar o laço:

Aluno a;

while (fread(&a, sizeof(Aluno), 1, arq) == 1) {
    printf("%d - %s - %.1f\n", a.ra, a.nome, a.nota);
}

Exemplo completo: cadastro persistente

#include <stdio.h>

typedef struct {
    int   ra;
    char  nome[50];
    float nota;
} Aluno;

void grava(const char *nome_arq) {
    FILE *arq = fopen(nome_arq, "ab");    // acrescenta ao final
    if (arq == NULL) return;

    Aluno a;
    printf("RA: ");
    scanf("%d", &a.ra);
    printf("Nome: ");
    scanf(" %49[^\n]", a.nome);
    printf("Nota: ");
    scanf("%f", &a.nota);

    fwrite(&a, sizeof(Aluno), 1, arq);
    fclose(arq);
}

void lista(const char *nome_arq) {
    FILE *arq = fopen(nome_arq, "rb");
    if (arq == NULL) {
        printf("Nenhum aluno cadastrado.\n");
        return;
    }

    Aluno a;
    while (fread(&a, sizeof(Aluno), 1, arq) == 1)
        printf("%d - %-30s %.1f\n", a.ra, a.nome, a.nota);
    fclose(arq);
}

int main(void) {
    int op;
    do {
        printf("\n1-Cadastrar  2-Listar  0-Sair: ");
        scanf("%d", &op);
        if (op == 1) grava("alunos.dat");
        else if (op == 2) lista("alunos.dat");
    } while (op != 0);
    return 0;
}

Cadastre alguns alunos, feche o programa, execute de novo e liste: os dados continuam lá. Depois abra alunos.dat no Bloco de Notas e observe o resultado.

Acesso aleatório: fseek, ftell e rewind

Todo arquivo aberto tem um indicador de posição, um "cursor" que avança automaticamente a cada leitura ou escrita. Até agora sempre lemos do início ao fim (acesso sequencial). Com as funções abaixo podemos mover o cursor livremente (acesso aleatório, ou direto):

int  fseek(FILE *arq, long deslocamento, int origem);
long ftell(FILE *arq);       // posição atual, em bytes desde o início
void rewind(FILE *arq);      // volta ao início (= fseek(arq, 0, SEEK_SET))
origemO deslocamento é contado a partir do…
SEEK_SETinício do arquivo
SEEK_CURposição atual
SEEK_ENDfinal do arquivo

Como cada registro ocupa sizeof(Aluno) bytes, o registro de índice k começa no byte k * sizeof(Aluno):

Contando registros sem ler o arquivo

fseek(arq, 0, SEEK_END);
long n = ftell(arq) / sizeof(Aluno);
rewind(arq);

Alterando o registro k no próprio arquivo

O modo "r+b" permite ler e escrever sem apagar o conteúdo:

void altera_nota(const char *nome_arq, int k, float nova) {
    FILE *arq = fopen(nome_arq, "r+b");
    if (arq == NULL) return;

    Aluno a;
    fseek(arq, k * sizeof(Aluno), SEEK_SET);
    if (fread(&a, sizeof(Aluno), 1, arq) == 1) {
        a.nota = nova;
        fseek(arq, k * sizeof(Aluno), SEEK_SET);   // volta ao início do registro
        fwrite(&a, sizeof(Aluno), 1, arq);
    }
    fclose(arq);
}

O segundo fseek é necessário porque o fread avançou o cursor para o registro seguinte. Além disso, o padrão C exige um fseek (ou rewind) entre uma leitura e uma escrita no mesmo arquivo.

E em arquivo texto?

Não funciona da mesma forma: as linhas têm tamanhos diferentes, então não há como calcular onde começa a linha k sem ler todas as anteriores.

Windows e o '\n'

No Windows, o modo texto converte '\n' em "\r\n" ao gravar, e o contrário ao ler. Por isso, ao gravar structs com fwrite, sempre use o b: sem ele, um byte que valha 10 (o código de '\n') dentro de um int seria alterado.

Exercícios de laboratório

Resolva em ordem: cada bloco reaproveita os arquivos e tipos do anterior. Compile sempre com gcc -Wall e deixe os arquivos de dados na mesma pasta do executável.

Modo texto

1. Contador. Leia o nome de um arquivo texto do teclado e informe quantos caracteres, linhas e palavras ele possui, como o comando wc do Linux. Teste com o próprio arquivo .c do exercício.

2. Cópia em maiúsculas. Escreva int copia_maiusculo(const char *origem, const char *destino), que copia um arquivo texto para outro convertendo as letras para maiúsculas (toupper, de <ctype.h>). Retorne 0 em caso de sucesso e 1 se algum arquivo não puder ser aberto.

3. Diário de bordo. Leia uma frase do teclado e acrescente-a ao arquivo diario.txt, precedida do número da entrada (#1, #2, …). Dica: antes de acrescentar, conte quantas linhas o arquivo já tem.

4. Boletim em CSV. Crie, em um editor ou planilha, o arquivo turma.csv com o cabeçalho RA;Nome;P1;P2;Trabalho. Leia-o para um vetor de structs, calcule a média de cada aluno (0.4*P1 + 0.4*P2 + 0.2*Trabalho) e gere boletim.csv com RA;Nome;Media;Situacao (Aprovado se média ≥ 6, senão Reprovado). Abra o resultado na planilha.

Modo binário

5. Vetor persistente. Leia n números float em um vetor alocado com malloc e grave-os em numeros.bin com um único fwrite. Em um segundo programa, descubra quantos números existem usando fseek/ftell, aloque um vetor do tamanho exato, leia tudo com um único fread e mostre a média. Compare o tamanho de numeros.bin com o de um arquivo texto com os mesmos números.

6. Cadastro completo. Estenda o cadastro persistente com as opções:

  • Buscar por RA (leitura sequencial até encontrar);
  • Consultar o registro de número k (acesso direto com fseek);
  • Alterar a nota de um aluno encontrado pelo RA (modo "r+b").

7. Conversor. Escreva um programa que converta o turma.csv do exercício 4 em turma.dat (binário de structs) e outro que faça o caminho inverso. Verifique que, após ida e volta, o CSV gerado tem o mesmo conteúdo do original.

8. Desafio: ranking do campeonato

Dado um CSV com os jogos de um campeonato (rodada;mandante;gols_mandante;gols_visitante;visitante), monte a tabela de classificação em um vetor de structs Time (nome, pontos, vitórias, empates, derrotas, gols pró, gols contra), ordene por pontos e saldo de gols e grave:

  • classificacao.csv, para ser aberta em uma planilha;
  • classificacao.dat, binário, que um segundo programa deve ler para responder "qual a posição do time X?" e "quem está na posição k?" (esta última com fseek).

Respostas dos quizzes "Verifique seu entendimento" de cada parte, com a justificativa de cada alternativa correta.

Parte 1 — Por que arquivos

  1. 1. b) Porque eles estão na memória principal, que é volátil— Variáveis e vetores vivem na RAM, que só guarda dados enquanto o programa executa. Para persistir, é preciso gravar na memória secundária, em um arquivo.
  2. 2. c) Guardam caracteres legíveis, organizados em linhas— Arquivo texto guarda caracteres (um por dígito, no caso dos números) separados em linhas por '\n'. As outras alternativas descrevem o arquivo binário.

Parte 2 — Abrindo e fechando

  1. 1. c) O conteúdo anterior é apagado— O modo "w" trunca o arquivo: o conteúdo anterior é perdido sem aviso. Para escrever depois das linhas existentes, use "a".
  2. 2. b) "rb"— "r" é leitura e o sufixo b indica modo binário. "wb" e "ab" são modos de escrita.

Parte 3 — Modo texto

  1. 1. b) Para que seja possível distinguir o valor EOF de um caractere válido— fgetc devolve qualquer um dos 256 valores de byte ou EOF (-1). Um char não tem espaço para representar os 257 casos, e EOF poderia ser confundido com um caractere.
  2. 2. b) 3— As três leituras retornam 2 e o corpo executa; a quarta tentativa retorna EOF e o laço termina. Com while (!feof(arq)) a última linha seria processada duas vezes.
  3. 3. b) Lê até 29 caracteres, parando no primeiro ;— [^;] é o conjunto de todos os caracteres exceto ';' e 29 é o limite máximo. É assim que se lê um campo de CSV com espaços.

Parte 4 — Modo binário

  1. 1. c) 0— fread retorna quantos elementos conseguiu ler. Sem dados restantes, retorna 0, por isso o laço compara com == 1.
  2. 2. b) fseek(arq, 4 * sizeof(Aluno), SEEK_SET);— Os registros são numerados a partir de 0, como nos vetores: o quinto é o de índice 4, que começa no byte 4 * sizeof(Aluno).
  3. 3. d) "r+b"— "r+b" lê e escreve a partir do início sem truncar. "wb" e "w+b" apagam o arquivo; "ab" só escreve no final.
