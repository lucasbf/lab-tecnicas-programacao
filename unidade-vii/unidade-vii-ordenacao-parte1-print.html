Ordenar para encontrar depois

Ordenar dados é fundamental, uma vez que teremos que encontrá-los depois. Pense na lista de chamada da turma, no dicionário, nos contatos do celular ou na tabela de classificação do campeonato: todos são úteis porque estão em ordem. Sem ordem, a única forma de encontrar alguma coisa é olhar item por item, do primeiro ao último.

Ordenar é tão comum que vários algoritmos foram propostos para isso, e eles precisam ser avaliados: todos chegam ao mesmo vetor ordenado, mas não com o mesmo custo.

Eficácia

O algoritmo resolve o problema? Ao final, o vetor está ordenado? É o mínimo que se espera de qualquer algoritmo.

"funciona?"

Eficiência

Quanto custa resolver? Quanto tempo e quanta memória o algoritmo consome para chegar ao resultado?

"funciona bem?"

Nesta primeira parte vamos estudar três algoritmos ineficientes, mas simples: Insertion Sort, Selection Sort e Bubble Sort. Eles são o ponto de partida para entender como se mede o custo de um algoritmo e por que existem algoritmos melhores, que veremos na Parte II junto com os métodos de pesquisa.

Como avaliar a eficiência de um algoritmo

Medir o tempo com um cronômetro não basta: o mesmo programa roda mais rápido em um computador novo do que em um antigo. Precisamos de uma medida que dependa do algoritmo, e não da máquina. Por isso avaliamos como o custo cresce em função do tamanho da entrada n. Para ordenação, n é o número de elementos do vetor.

  • Complexidade de tempo: mede a quantidade de tempo que o algoritmo leva para ser executado com base no tamanho de entrada n. Na prática, contamos operações (comparações, trocas) em vez de segundos.
  • Complexidade de espaço: avalia a quantidade de memória adicional que o algoritmo precisa para armazenar variáveis, estruturas de dados temporárias e outros elementos durante a execução.

Contando operações

A função abaixo conta quantos pares (i, j), com i < j, estão fora de ordem em um vetor. Esses pares se chamam inversões e vão reaparecer mais adiante.

int conta_inversoes(int v[], int n) {
    int total = 0;
    for (int i = 0; i < n - 1; i++)
        for (int j = i + 1; j < n; j++)
            if (v[i] > v[j])        // quantas vezes esta linha executa?
                total++;
    return total;
}

Para i = 0 o laço interno executa n - 1 vezes; para i = 1, n - 2 vezes; e assim até i = n - 2, que executa 1 vez. No total:

(n-1) + (n-2) + ... + 2 + 1  =  n(n-1)/2  ≈  n²/2

Para n = 1000 são 499.500 comparações. Se o vetor dobrar (n = 2000), são 1.999.000: quatro vezes mais. Esse é o comportamento típico de um algoritmo quadrático. Já a memória adicional é só a das variáveis i, j e total, que não depende de n: espaço constante.

Guarde esta soma

1 + 2 + … + (n-1) = n(n-1)/2. Ela aparece sempre que um laço interno percorre "o que sobrou" do vetor, e é a origem do n² nos três algoritmos desta unidade.

Notação Big-O

A notação Big-O indica o limite superior do tempo de execução no pior caso, ou seja, o tempo (ou espaço) máximo que o algoritmo levará. Ela despreza constantes e termos menores: n²/2 + n/2 é simplesmente O(n²), porque para n grande é o n² que manda.

Insertion Sort: ideia e exemplo

Ordenação por inserção

  1. Percorrer o vetor da esquerda para a direita;
  2. Para cada elemento, compará-lo com os elementos à sua esquerda;
  3. Caso o elemento à esquerda seja maior, trocar os dois elementos de lugar;
  4. Repetir o processo até que o elemento seja menor que o elemento à sua esquerda ou que chegue à primeira posição do vetor.

É o que fazemos ao organizar cartas de baralho na mão: pegamos a carta seguinte e a deslizamos para a esquerda até encontrar o lugar dela entre as que já estão ordenadas. A parte ordenada cresce da esquerda para a direita, mas um elemento ali ainda pode ser empurrado para dar lugar a outro.

Insertion Sort: código e características

void insertion_sort(int vet[], int t) {
    for (int i = 1; i < t; i++) {
        int j = i;
        int key = vet[i];
        while (j > 0 && vet[j-1] > key) {
            vet[j] = vet[j-1];
            j--;
        }
        vet[j] = key;
    }
}
  • O laço externo começa em i = 1: um vetor de um elemento (vet[0]) já está ordenado.
  • key guarda o elemento que está sendo inserido. Em vez de fazer uma troca completa a cada passo, o código desloca os maiores uma posição para a direita (vet[j] = vet[j-1]) e só no final coloca key na vaga que sobrou. O efeito é o mesmo da ideia geral ("trocar com o da esquerda"), com menos atribuições.
  • A ordem das condições no while importa: j > 0 é testado antes de vet[j-1]. Quando j chega a 0, o && para na primeira condição e vet[-1] nunca é acessado.

Características

CasoComplexidadeQuando acontece
Pior casoO(n²)vetor em ordem decrescente: cada key percorre toda a parte ordenada
Melhor casoΩ(n)vetor já ordenado: 1 comparação por passada, n - 1 no total
Caso médioΘ(n²)vetor aleatório: cada key anda, em média, metade da parte ordenada (≈ n²/4)
  • Espaço: O(1). Usa apenas i, j e key, qualquer que seja n: ordena no próprio vetor.
  • É adaptativo: quanto mais ordenado o vetor já estiver, mais rápido ele termina. Por isso é ótimo para vetores quase ordenados.

Selection Sort: ideia e exemplo

Ordenação por seleção

  1. Para cada índice do vetor, da esquerda para a direita, faça:
    1. Encontre o menor elemento do subvetor à direita deste índice (a partir dele);
    2. Troque o elemento do índice com o menor elemento encontrado.

A cada passada, um elemento vai direto para sua posição definitiva: na passada 1 o menor de todos vai para a posição 0, na passada 2 o segundo menor vai para a posição 1, e assim por diante.

Selection Sort: código e características

void selection_sort(int vet[], int t) {
    for (int i = 0; i < t; i++) {
        int key = i;
        for (int j = i; j < t; j++) {
            if (vet[j] < vet[key])
                key = j;
        }
        int aux = vet[i];
        vet[i] = vet[key];
        vet[key] = aux;
    }
}
  • Aqui key não é um valor, é um índice: a posição do menor elemento encontrado até agora.
  • O laço interno sempre percorre todo o subvetor vet[i..t-1], não importa como os dados estejam. O número de comparações é sempre o mesmo para um dado n.
  • Há no máximo uma troca por passada: no total, até n trocas. Nenhum dos outros dois algoritmos move tão pouco os dados.
Melhorando o código

Duas mudanças pequenas eliminam trabalho inútil sem alterar o resultado: o laço interno pode começar em j = i + 1, porque comparar vet[i] com ele mesmo nunca muda key; e o laço externo pode ir só até i < t - 1, porque quando sobra um único elemento ele já está no lugar. Com as duas, as comparações caem de n(n+1)/2 para n(n-1)/2. Também é comum só trocar if (key != i).

Características

CasoComplexidadeQuando acontece
Pior casoO(n²)qualquer vetor
Melhor casoΩ(n²)mesmo já ordenado, procura o menor em todo o subvetor restante
Caso médioΘ(n²)qualquer vetor
  • Espaço: O(1).
  • Não é adaptativo: a ordem dos dados não muda o número de comparações.
  • Vantagem: faz apenas O(n) trocas. É útil quando mover dados é bem mais caro do que comparar (registros grandes, memória flash).

Bubble Sort: ideia e exemplo

Ordenação por troca

  1. Para cada índice do vetor, da direita para a esquerda, faça:
    1. A partir do índice i = 0, compare os elementos vizinhos (i, i+1);
    2. Caso o elemento em i seja maior que o elemento em i+1, trocar.

A cada passada, o maior elemento ainda fora do lugar é empurrado para a direita, como uma bolha que sobe, até parar no fim da parte não ordenada. A parte ordenada cresce da direita para a esquerda.

Bubble Sort: código e características

void bubble_sort(int vet[], int t) {
    for (int i = t-1; i > 0; i--) {
        for (int j = 0; j < i; j++) {
            if (vet[j] > vet[j+1]) {
                int aux = vet[j];
                vet[j] = vet[j+1];
                vet[j+1] = aux;
            }
        }
    }
}
  • i marca o fim da parte não ordenada. Depois de cada passada, vet[i] está na posição definitiva, por isso o laço interno vai só até j < i.
  • No exemplo, o vetor já estava ordenado após a passada 5, mas esse código faz todas as n - 1 passadas: são sempre n(n-1)/2 comparações.

Parando mais cedo: a versão com trocou

Se uma passada inteira acontecer sem nenhuma troca, todos os vizinhos estão em ordem e o vetor está ordenado. Basta um indicador para parar:

void bubble_sort(int vet[], int t) {
    for (int i = t-1; i > 0; i--) {
        int trocou = 0;
        for (int j = 0; j < i; j++) {
            if (vet[j] > vet[j+1]) {
                int aux = vet[j];
                vet[j] = vet[j+1];
                vet[j+1] = aux;
                trocou = 1;
            }
        }
        if (!trocou)        // passada sem trocas: já está ordenado
            break;
    }
}

Com um vetor já ordenado, essa versão faz uma única passada de n - 1 comparações e termina. É ela que tem melhor caso Ω(n). No exemplo, pararia na passada 6, a primeira sem trocas.

Características

CasoComplexidadeQuando acontece
Pior casoO(n²)vetor em ordem decrescente: toda comparação gera uma troca
Melhor casoΩ(n)vetor já ordenado, na versão com trocou

  • Espaço: O(1).
  • É o mais simples de escrever, mas costuma ser o mais lento dos três na prática: faz tantas trocas quanto o Insertion faz deslocamentos, e cada troca custa 3 atribuições.

Parte 1 — Avaliando algoritmos

  1. 1. b) resolve corretamente o problema— Eficácia é resolver o problema: o vetor termina ordenado. Tempo e memória são questões de eficiência.
  2. 2. c) 8 segundos— Dobrar n em um algoritmo quadrático multiplica o tempo por 2² = 4: 2 s × 4 = 8 s.

Parte 2 — Insertion Sort

  1. 1. b) Para que vet[j-1] não seja acessado quando j vale 0— O && avalia da esquerda para a direita e para no primeiro falso. Com j == 0, vet[j-1] seria vet[-1], fora do vetor.
  2. 2. b) 99— São 99 passadas (i de 1 a 99) e, em cada uma, o while falha na primeira comparação: n − 1 = 99. Esse é o melhor caso Ω(n).

Parte 3 — Selection Sort

  1. 1. b) O índice do menor elemento encontrado até agora— key começa em i e é atualizada para j sempre que vet[j] < vet[key]: é uma posição, não um valor.
  2. 2. c) Selection Sort— O laço interno do Selection sempre percorre todo o subvetor restante para ter certeza de qual é o menor, independentemente da ordem dos dados.

Parte 4 — Bubble Sort e comparação

  1. 1. b) 2 4 1 3 7— (4,2) troca → 2 4 7 1 3; (4,7) não; (7,1) troca → 2 4 1 7 3; (7,3) troca → 2 4 1 3 7. O maior (7) chegou ao fim.
  2. 2. a) Insertion Sort— O Insertion é adaptativo: os itens já ordenados custam 1 comparação cada, e só os novos andam para a esquerda. O Selection e o Bubble sem trocou fazem sempre ≈ n²/2 comparações.
