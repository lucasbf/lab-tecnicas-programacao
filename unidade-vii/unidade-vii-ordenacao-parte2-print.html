Além do O(n²)

Na Parte I vimos três algoritmos simples: Insertion, Selection e Bubble Sort. Todos são O(n²): dobrar o tamanho do vetor quadruplica o tempo. Com um milhão de elementos, isso significa cerca de um trilhão de operações.

O defeito comum aos três é que eles movem os elementos uma posição por vez, ou comparam cada elemento com todos os outros. Nesta segunda parte veremos três algoritmos que contornam esse problema de formas diferentes:

Shell Sort: ideia e exemplo

Inserção com saltos

Contextualização

  • Proposto por Donald Shell (1959).
  • É uma extensão do Insertion Sort. Lembre da ideia geral: cada elemento (key) é deslizado para a esquerda até encontrar seu lugar na parte já ordenada.
  • Problemas do Insertion Sort:
    • Ele troca itens adjacentes para determinar o ponto de inserção: cada elemento anda uma posição por vez.
    • São efetuadas n - 1 trocas quando o menor item está na posição mais à direita do vetor: ele atravessa o vetor inteiro, de vizinho em vizinho.
    • É ineficiente para n grande: O(n²).
  • O Shell Sort contorna esse problema criando um gap (distância, salto) de troca: um elemento pode andar h posições de uma vez.

Ideia básica

  1. Os itens separados por h posições (o gap) são rearranjados com o Insertion Sort, gerando sequências ordenadas.
  2. Dizemos que cada sequência é h-ordenada: pegando um elemento a cada h posições, o que sobra está em ordem.
  3. O valor de h é reduzido progressivamente até h = 1. A passada com h = 1 é um Insertion Sort comum, que termina com o vetor ordenado.

Os primeiros saltos, grandes, levam os elementos para perto do lugar certo com poucos movimentos. Quando chega a vez de h = 1, o vetor já está quase ordenado, e o Insertion Sort é rápido nesse caso (melhor caso Ω(n), lembra?).

Shell Sort: código e o valor de h

void shell_sort(int vet[], int n) {
    int i, j, h, aux;

    h = 1;
    while (h < n)
        h = 3 * h + 1;

    do {
        h = (h - 1) / 3;
        for (i = h; i < n; i++) {
            aux = vet[i];
            j = i;
            while (j >= h && vet[j - h] > aux) {
                vet[j] = vet[j - h];
                j -= h;
            }
            vet[j] = aux;
        }
    } while (h != 1);
}
  • Calculando o primeiro h: o while gera a sequência 1, 4, 13, 40, 121, 364, ... até passar de n. Para n = 8, para em h = 13.
  • No do-while: a primeira linha desfaz um passo da sequência (h = (h - 1) / 3), voltando para o maior h menor que n. Para n = 8: 13 → 4 → 1. Quando a passada com h = 1 termina, o while (h != 1) encerra o laço.
  • O corpo do for é o Insertion Sort da Parte I, trocando 1 por h: aux faz o papel de key, a comparação é com vet[j - h] (o vizinho a h posições) e o deslocamento é vet[j] = vet[j - h]. Com h = 1, o código fica idêntico ao Insertion Sort.
  • O for percorre i de h até n - 1 uma vez só, e as subsequências são tratadas intercaladas: i = h trabalha na subsequência 0, i = h + 1 na subsequência 1, e assim por diante.
Cuidado com n = 1

Com um único elemento, h começa em 1 e não entra no while; no do, h = (1 - 1) / 3 = 0, e o while (h != 1) nunca termina: laço infinito. Antes de usar a função, proteja-a com if (n < 2) return; no início.

O valor de h (gap) importa

  • h foi inicialmente proposto como valores múltiplos de 2 (n/2, n/4, ..., 1), e era ineficiente: com saltos todos pares, elementos em posições pares e ímpares só são comparados entre si na última passada (h = 1).
  • Donald Knuth propôs empiricamente uma fórmula para h que apresenta eficiência satisfatória:
    • Para s = 1: h(s) = 1
    • Para s > 1: h(s) = 3 · h(s − 1) + 1
    Isso gera 1, 4, 13, 40, 121, 364, 1093, ..., exatamente a sequência usada no código.
  • Existem diversas sequências de h propostas, cada uma com suas particularidades (Shell, Hibbard, Sedgewick, Ciura...).

Características

  • A complexidade do Shell Sort ainda não é conhecida. Sua análise depende de problemas matemáticos difíceis e sofre forte influência da própria sequência de h.
  • O que se sabe é que h não deve ser múltiplo do anterior. Trata-se de uma observação empírica, experimental.
  • Conjecturas referentes ao número de comparações para a sequência de Knuth: C₁(n) = O(n1,25) e C₂(n) = O(n (ln n)²).
O que é uma conjectura?

Conjecturas são comuns na matemática, nas ciências e em outras áreas do conhecimento: pesquisadores observam um padrão ou uma regularidade e propõem uma conjectura para tentar descrevê-lo. No entanto, enquanto uma conjectura não for provada ou refutada, ela permanece no campo das hipóteses.

  • Espaço: O(1). Usa só i, j, h e aux: ordena no próprio vetor.
  • Não é estável: os saltos podem fazer um elemento "pular" outro de mesma chave.

Dividir para conquistar

Os próximos dois algoritmos pertencem à família chamada dividir para conquistar (divide and conquer):

  • Quebrar o problema em versões menores, resolvendo estas e aproveitando a solução para resolver o problema todo.
  • Dividir o problema em vários subproblemas e resolver esses subproblemas através da recursividade (Unidade III).
  • Conquistar: após todos os subproblemas terem sido resolvidos, ocorre a conquista, que é a união das resoluções dos subproblemas.
Atenção: o problema deve ser decomponível

Deve ser possível decompor qualquer instância não trivial do problema em instâncias menores do mesmo tipo de problema: uma instância é composta por instâncias menores do próprio problema. É a natureza recursiva do problema. Ordenação é decomponível: ordenar 8 números pode ser feito ordenando dois grupos de 4.

Toda recursão precisa de um caso base, que não se divide mais. Na ordenação, o caso base é o vetor de um elemento: ele já está ordenado.

Merge Sort: ideia e exemplo

Ordenação por intercalação

Ideia geral

  1. Dividir: calcula o ponto médio do vetor, dividindo-o em 2 subvetores.
  2. Conquistar: recursivamente ordena os dois subvetores, cada um de tamanho n/2.
  3. Combinar: une (intercala, merge) os dois subvetores ordenados num único vetor ordenado.

Exemplo: 6 5 3 1 8 7 2 4

Como funciona a intercalação

Intercalar dois vetores já ordenados é fácil: compare os primeiros de cada um, copie o menor para o vetor auxiliar e avance naquele vetor. Veja a última intercalação, de 1 3 5 6 com 2 4 7 8:

Merge Sort: código e características

Divisão: trivial.

void merge_sort(int vet[], int inicio, int fim) {
    if (inicio < fim) {
        int meio = (inicio + fim) / 2;
        if (inicio < meio)
            merge_sort(vet, inicio, meio);
        if (meio + 1 < fim)
            merge_sort(vet, meio + 1, fim);
        merge(vet, inicio, meio, fim);
    }
}

Conquista: trabalhosa.

void merge(int vet[], int inicio, int meio, int fim) {
    int aux[fim - inicio], i, j, k;
    for (i = inicio, j = meio + 1, k = 0; i <= meio && j <= fim; k++) {
        if (vet[i] <= vet[j]) {
            aux[k] = vet[i];
            i++;
        } else {
            aux[k] = vet[j];
            j++;
        }
    }
    if (i <= meio) {
        for (j = meio; j >= i; j--) {
            vet[fim - meio + j] = vet[j];
        }
    }
    for (i = 0; i < k; i++)
        vet[i + inicio] = aux[i];
}

Chamada no main: merge_sort(vet, 0, n - 1);. Os índices inicio e fim são inclusivos. Como merge é usada antes de ser definida, coloque-a antes de merge_sort no arquivo (ou declare seu protótipo).

  • merge_sort: só calcula o meio e chama a si mesma para as duas metades. Os if (inicio < meio) e if (meio + 1 < fim) evitam chamadas para subvetores de um elemento (o caso base, que já está ordenado).
  • merge, laço for: i percorre a metade esquerda vet[inicio..meio], j a metade direita vet[meio+1..fim] e k o vetor auxiliar. O laço para quando uma das metades acaba.
  • Usar <= (e não <) faz o Merge Sort ser estável: em caso de empate, o elemento da esquerda vai primeiro.
  • Sobras: se a metade direita acabou primeiro, as sobras da esquerda são movidas para o final do trecho (vet[fim - meio + j] = vet[j], de trás para frente, para não sobrescrever). Se a metade esquerda acabou primeiro, as sobras da direita já estão no lugar certo e nada precisa ser feito.
  • Cópia de volta: os k elementos de aux voltam para vet[inicio..].
  • int aux[fim - inicio] é um vetor de tamanho variável (padrão C99), alocado na pilha a cada chamada. Ele tem um elemento a menos que o trecho, e isso basta: o laço termina quando uma metade acaba, então pelo menos um elemento sempre sobra fora do aux.

Características

CasoComplexidadeQuando acontece
Pior casoO(n log₂ n)qualquer vetor
Melhor casoΩ(n log₂ n)qualquer vetor: o Merge sempre divide ao meio e sempre intercala
Caso médioΘ(n log₂ n)qualquer vetor
Por que n log₂ n?

O vetor é dividido ao meio até sobrar 1 elemento: são log₂ n níveis (para n = 8, 3 níveis; para n = 1.000.000, cerca de 20). Em cada nível, as intercalações juntas passam por todos os n elementos (veja a Figura 2). Total: n × log₂ n.

  • Espaço: O(n). Precisa de memória auxiliar para intercalar, mais a pilha da recursão (O(log n)). É o preço da garantia de O(n log n).
  • Estável, graças ao <=.
  • Não é adaptativo: um vetor já ordenado custa praticamente o mesmo que um aleatório (a ordem só reduz as comparações de cada merge, não o número de níveis).

Quick Sort: ideia e exemplo

Ordenação por partição

Mais um algoritmo recursivo de dividir para conquistar, proposto por C. A. R. Hoare (1960). Entretanto, aqui é o contrário do Merge Sort: a fase de divisão é trabalhosa, enquanto a conquista é trivial.

Ideia geral

  1. Escolha um elemento da lista, denominado pivô.
  2. Particiona: rearranje a lista de forma que todos os elementos anteriores ao pivô sejam menores que ele, e todos os elementos posteriores sejam maiores. Ao fim do processo, o pivô estará em sua posição final e haverá duas sublistas não ordenadas. Essa operação é denominada partição.
  3. Recursivamente ordene a sublista dos elementos menores e a sublista dos elementos maiores.

Não há "combinar": depois que as duas sublistas estão ordenadas, o vetor inteiro já está ordenado (menores | pivô | maiores).

Exemplo: 6 5 3 1 8 7 2 4

No código dos slides, o pivô é sempre o primeiro elemento do trecho (vet[inicio]). Na partição, i procura, da esquerda, alguém maior que o pivô; j procura, da direita, alguém menor ou igual. Quando os dois param, trocam.

Quick Sort: código e características

void troca(int *a, int *b) {
    int aux = *a;
    *a = *b;
    *b = aux;
}

Divisão: trabalhosa.

int particao(int vet[], int inicio, int fim) {
    int i = inicio + 1;
    int j = fim;
    int pivo = vet[inicio];

    while (i <= j) {
        while (i <= j && vet[i] <= pivo)
            i++;
        while (j > i && vet[j] > pivo)
            j--;
        if (i <= j) {
            troca(&vet[i], &vet[j]);
            i++;
            j--;
        }
    }
    troca(&vet[inicio], &vet[j]);
    return j;
}

Conquista: trivial.

void quick_sort(int vet[], int inicio, int fim) {
    int j = particao(vet, inicio, fim);
    if (inicio < j - 1)
        quick_sort(vet, inicio, j - 1);
    if (j + 1 < fim)
        quick_sort(vet, j + 1, fim);
}

Chamada no main: quick_sort(vet, 0, n - 1);, com n ≥ 1.

  • troca recebe ponteiros (Unidade IV): &vet[i] é o endereço da posição i, e a função troca os valores no próprio vetor.
  • particao: o pivô é vet[inicio]. i avança enquanto encontra elementos ≤ pivô (já estão do lado certo); j recua enquanto encontra elementos > pivô. Se os dois pararam sem se cruzar, vet[i] e vet[j] estão do lado errado: troca. Quando se cruzam, j aponta para o último elemento ≤ pivô, e a troca final coloca o pivô entre as duas partes, na sua posição definitiva.
  • quick_sort: particiona e chama a si mesma para vet[inicio..j-1] (menores) e vet[j+1..fim] (maiores). Os if evitam chamadas para trechos com 0 ou 1 elemento.

Características

CasoComplexidadeQuando acontece

Por que O(n²) no pior caso?

Com o vetor 1 2 3 4 5 6 7 8, o pivô 1 já está no lugar: sobra um lado com 7 elementos. Depois o pivô 2 deixa 6, e assim por diante. São n - 1 partições, com 7 + 6 + ... + 1 = 28 = n(n-1)/2 comparações: a mesma soma da Parte I.

  • Espaço: não usa vetor auxiliar, só a pilha da recursão: O(log n) no caso médio, O(n) no pior caso. Com n grande, o pior caso pode estourar a pilha.
  • Não é estável: as trocas de longa distância podem inverter elementos iguais.
  • Apesar do pior caso, costuma ser o mais rápido na prática: suas operações são simples e ele acessa a memória de forma sequencial. Para evitar o pior caso, escolhe-se o pivô de forma mais esperta: o elemento do meio, um elemento aleatório ou a mediana de três (primeiro, meio e último).

Como escolher

  • Vetor pequeno ou quase ordenado: Insertion Sort.
  • Garantia de O(n log n) e estabilidade (por exemplo, ordenar registros por um segundo critério): Merge Sort, se houver memória.
  • Mais rápido na média, sem memória extra: Quick Sort, com uma boa escolha de pivô.
  • Simples, sem recursão e sem memória extra, bem melhor que O(n²): Shell Sort.

Parte 1 — Shell Sort

  1. 1. b) O Shell Sort é um Insertion Sort aplicado com saltos h que diminuem até 1— O corpo do for é o Insertion Sort com 1 trocado por h. A última passada, com h = 1, é exatamente o Insertion Sort da Parte I.
  2. 2. c) 40, 13, 4, 1— O while gera 1, 4, 13, 40, 121 e para em 121 (primeiro ≥ 100). O do-while começa com (121 − 1) / 3 = 40 e segue 13, 4, 1.
  3. 3. c) Não é conhecida com exatidão; há conjecturas como O(n^1,25)— A análise depende de problemas matemáticos difíceis e da sequência de h. Para Knuth, há conjecturas (ainda não provadas) como O(n^1,25).

Parte 2 — Dividir para conquistar e Merge Sort

  1. 1. b) Na intercalação (merge), na volta da recursão— Dividir é só calcular meio = (inicio + fim) / 2. O trabalho de comparar e copiar está no merge, executado depois das chamadas recursivas.
  2. 2. b) 10— Cada nível divide o tamanho por 2: 1024 → 512 → ... → 1 são log₂ 1024 = 10 níveis.
  3. 3. b) Porque a intercalação usa um vetor auxiliar— Intercalar no próprio vetor sobrescreveria elementos ainda não usados; por isso o merge copia para aux e depois devolve. Na intercalação final, aux tem quase n posições.

Parte 3 — Quick Sort e comparação

  1. 1. b) O pivô está na sua posição final, com menores ou iguais à esquerda e maiores à direita— A partição só garante a posição do pivô e o lado de cada elemento. Os dois lados continuam desordenados e podem ter tamanhos bem diferentes.
  2. 2. b) Um vetor já ordenado— Com o vetor ordenado, o pivô (primeiro elemento) é sempre o menor do trecho: um lado fica vazio e o outro com n − 1 elementos, e as comparações somam n(n−1)/2.
  3. 3. b) Merge Sort— O Merge Sort é O(n log n) em todos os casos; o custo é a memória auxiliar O(n), que aqui não é problema. O Quick tem pior caso O(n²); Bubble e Selection são sempre O(n²).

Exercício 3 — corrigindo o Shell Sort

Calcule o maior h da sequência menor que n e use um while que testa antes de executar. Para n = 0 ou n = 1, a passada com h = 1 não faz nada e h vira 0, encerrando o laço:

void shell_sort(int vet[], int n) {
    int i, j, h, aux;

    h = 1;
    while (3 * h + 1 < n)
        h = 3 * h + 1;

    while (h >= 1) {
        for (i = h; i < n; i++) {
            aux = vet[i];
            j = i;
            while (j >= h && vet[j - h] > aux) {
                vet[j] = vet[j - h];
                j -= h;
            }
            vet[j] = aux;
        }
        h = (h - 1) / 3;
    }
}
